## 背景与目标
四象限任务管理器，按天管理「重要 / 紧急」两个维度的四类任务，纯前端实现，可经 Capacitor 打包为安卓 App。
**跑通最小可用闭环**
- 四象限视图
- 任务增删改
- 完成任务后勾选
- 拖拽排序 / 跨象限移动
- 数据互通（导出 / 导入 JSON）
- JSON、Markdown 格式导出
- JSON 格式导入
**落实「每个用户一份数据」**
存储层带用户维度，本期只有一个 `default` 用户（key 为 `quadrant_user_data:default`）。后续上线登录后，保留「将默认用户数据迁移至当前登录用户数据路径」的选项（登录后一键认领 / 合并）。本期只实现用户路径抽象，不实现账号。
**不依赖网络和第三方服务**
本版不联网、不需要账号、不需要服务器。数据全部存在用户自己的设备上，跨设备靠手动导出 / 导入 JSON。这条边界让核心功能可以独立交付、独立验收，不会被任何外部因素卡住。
先完成核心功能，再完成次要功能

## 功能列表
### P0：核心功能
网页版四象限主视图：2×2 网格布局（I 重要且紧急 / II 重要不紧急 / III 紧急不重要 / IV 不重要不紧急）。手机端安卓 APP 改为 1×4 布局。四象限背景颜色：I 红 / II 蓝 / III 黄 / IV 绿
日期管理：默认当天；日期选择器切换任意日期，各日期数据相互独立
任务增删改：
- 每个象限提供一个添加任务的入口（具体放在哪、长什么样，见 DS D-30）
- 单击任务文本进入编辑
- 删除按钮直接删除（无回收站，删除即永久）
阶段划分：
- 每个任务可以拆成若干个**阶段**（如「写季度报告」= 收集数据 → 写初稿 → 审阅 → 定稿）
- 每个阶段有自己的文字和完成状态；阶段可以增、删、改、勾选、排序
- **阶段只有一层**，阶段下面不能再分
- **有阶段的任务，它的完成状态只由阶段决定**；没有阶段的任务，它自己就是一个条目
- 阶段在界面上**默认折叠**，有阶段的任务点任务行右边的小三角展开；每条任务右上角有个小「＋」用来添加阶段（具体交互见 DS 2.9）
任务块：
- 每个象限标题栏右上角，在「＋」旁边再加一个符号，用来创建一个**任务块**（具体符号见 DS 2.10）
- 任务块有自己的名字；块内可以装若干条**任务**，任务可以拖进去、也可以拖出来
- 同一象限内，任务块之间、任务块与任务之间按**相对顺序混排**，先后都可以拖动调整
- 任务块可以像任务那样**跨象限拖动**，块内任务跟着一起走
- 块只有一层：块里只能装任务（任务可以有自己的阶段），**块里不能再装块**
- 块的完成状态只由块内任务决定；块的勾选框 = 一键勾上 / 取消块内全部任务
- 统计口径不变（按最细的可勾选单位算）：块自身不计数，数的是块内任务（有阶段算阶段）
- 空块合法：刚建出来的块就是空的，显示「把任务拖进来」的占位提示
计划池（一期）：
- 四象限的**下方**增加一个「计划池」面板，横向铺满一行，和四象限是两个独立区域
- 每个象限中的**顶层任务**行上添加「推迟」选项；点击推迟后，任务立即从原象限消失、自动出现在计划池里
- 推迟带走任务的全部内容：文字、完成状态、阶段（有阶段就连阶段一起进池）
- 计划池里的任务可以**拖回**任意象限（放到拖放时占位符指示的位置，不指定位置时排末尾），也可以删除；文字可编辑
- 计划池**不按日期分**，是一个全局列表；推迟进来的任务一直留在池中，直到被拖回象限或删除
- 计划池任务**不计入**顶部统计与象限计数（它们不在任何象限里）；勾选框隐藏 —— 池里是「待安排」的事，不是「正在做」的事
- 只有**顶层任务**提供「推迟」：任务块整体、块内任务不提供推迟按钮（要推迟块内任务，先把它拖出块；块是手动分组的整体，不随单个任务的推迟而拆散）
- 计划池内容随导出 / 导入一起走；30 天归档只按 `dates` 收缩，**不动计划池**
计划池（二期）：
- 池内任务可**手动设定完成时间**（一个日期）；未手动设定时时间为**空**，任务**持续保留**在池中，不会因为没设时间而被清掉或提醒
- **从象限推迟**进池的任务，完成时间默认为**下一天**（以被推迟任务所属的日期为基准 +1 天），允许用户修改
- **推迟「阶段」**：阶段行的「推迟」把这一条阶段从父任务里摘出来，**保存为池内的一条任务**，并在文本前用中括号标注所属任务，格式为 `[所属任务文本]阶段文本`；完成时间同样默认下一天
- 只允许推迟「任务」或「阶段」两种：任务块整体没有推迟入口（一期规矩不变），阶段是这一期新加的推迟对象
计划池（三期）：
- 计划池头部有「＋」入口，可**直接往池里添加任务**（点击在池列表末尾长出输入框，回车 / 失焦提交，Esc 取消 —— 和象限加任务同一套交互）；进池入口变为两个：象限「推迟」+ 池内「＋」，拖拽仍然不许进池
- 手动添加的任务，完成时间默认为**当前查看日期 + 7 天**（不是「未设定」——手动添加的语义是「近一周要做的事」，给一个明确但宽松的默认）；同样可修改、可清除回「未设定」
- 手动添加的任务与推迟进来的任务完全同构：可拖回象限、可删除、可改文字、计入导出导入
完成时段（二期）：
- 没有阶段的任务，任务行上直接有**完成时段**选项；划分了阶段的任务，任务本体**没有**这个选项（它的完成安排由各阶段决定，与统计「数最细单位」同口径），改为每个**阶段行**上各有一个
- 时段**六选一**：早上 / 上午 / 中午 / 下午 / 傍晚 / 晚上，用图标 + 文字展示；也可以随时清除回「未设定」
- 时段是**纯标记**：不参与排序、不影响勾选与统计；块内任务与顶层任务一样可设时段，任务块本体不设
- 时段随导出 / 导入一起走；时间视图（下一节需求）按它分组
时间视图：
- 四象限旁提供「时间视图」切换：点它把主区域换成**按完成时段分组**的当天任务展示，再点一次（或点「四象限」）切回；切换不改任何数据
- 只显示**有任务的时段**（当天有 4 个时段有任务就显示 4 组），时段按从早到晚的固定顺序排；没设时段的任务不进任何组
- 组内容：无阶段任务显示任务本体；有阶段任务显示**设了时段的那些阶段**（标注所属任务）；块内任务照常参与，块本体只是分组不出现
- 布局：**网页版两列网格**（组数自动排成两列多行，如 4 组即 2×2）；**手机端（≤600px）单列**，一行一组
- 时间视图**可操作**（v1.2 起）：条目支持勾选完成、点文字进编辑、删除、改完成时段，和象限视图操作的是同一份数据（条目类名与数据属性与象限一致）；不提供新增任务 / 阶段 / 块和拖拽（结构操作回四象限做）；时间视图下计划池面板照常显示、照常可用
模板：
- **缓存当天为模板**：把当前查看日期的四象限任务表（任务、阶段、任务块、勾选状态、完成时段，原样）存成一份模板；模板**不按日期分**，是全局列表
- 缓存时自动命名 = 当天日期串（如 `2026-10-01`）；**若用户没有重命名**，再次缓存同一天会**覆盖**同名（自动名）的模板项；若用户已重命名，再次缓存会**新建**一条自动名模板
- 模板可**重命名**（改空拒绝）和**删除**
- 模板可**应用到当前查看的日期**：往四象限里填充模板内容的副本（编号全部换新、勾选状态清零——模板是计划不是记录）；同一天同一象限已有同文本条目的跳过（防止重复应用出双份）
- 模板随导出 / 导入一起走（导入按名称判重，同名跳过）
四象限、日期、任务增删改、勾选、拖拽、持久化、统计、JSON 导入导出
完成勾选：checkbox 切换完成状态；完成态文字删除线 + 降低透明度
拖拽：同一象限内可以拖动任务顺序；跨象限也可以拖动任务所处象限位置。**网页版（鼠标）和移动端（手指）都要支持**
数据跨设备互通（**手动方式**）：导出 JSON → 在另一台设备上导入。不联网、不依赖任何服务
### P1：次要功能
亮 / 暗主题切换（UI 设置，不进入用户数据）
导出格式：导出本地全部用户数据为 .json 文件下载（离线备份通道），同时也支持导出为 Markdown / PDF 文件。网页版 Ctrl+S 直接保存 JSON 和 Markdown 两种格式的文件，PDF 另走浏览器的打印对话框由用户自己另存；移动端需要手动选择保存类型（包括第四种选择，包含 JSON + Markdown 两种格式的 .zip 压缩包）
导入功能：选择本地 .json 文件，**合并**进本地数据（如果某一任务的象限信息、文本内容和同一天已有任务完全一致，不做插入操作）。如果 JSON 文件格式有误，终止导入操作
勾选与统计：完成 / 取消完成后，顶部统计（已完成 / 总数 / 完成率）与勾选状态一致
本地体积控制：本地只保留最近 30 天数据，超出的部分自动归档成 JSON 文件下载给用户；**归档下载未成功时，不得删除本地数据**
### 非功能需求
纯原生实现：HTML / CSS / JS，页面运行时不引第三方库、无构建步骤；沿用 var + IIFE 风格（兼容 Capacitor WebView 与 file:// 场景）。打包安卓 App 所需的 Capacitor 及其插件属于**构建期依赖**，不受此限
性能：单日 ≤100 条任务时操作流畅；渲染与保存采用防抖合并
兼容：现代浏览器 + Capacitor WebView；安卓移动端（≤600px）可用
离线可用：**所有功能都不依赖网络**。断网状态下增删改查、导出、导入、归档全部正常
打包：可经 Capacitor 打包为安卓 App（打包所需的 Capacitor 属于构建期依赖，不受「不引第三方库」限制）
安卓端差异：额外用 Capacitor Preferences 存一份数据副本（防止系统回收 localStorage）；**导出里不提供 PDF**——安卓 WebView 没有实现打印，见 DS 4.4
### 非目标（本期明确不做）
给后续开发者（含 Claude Code）的硬约束：任何超出以下边界的功能需求一律拒绝或移入后续迭代，不得自行添加。
不做账号：无登录、无注册、无手机短信验证、无微信登录、无 Token / JWT、无任何用户身份体系、**无任何网络认证请求**
不做协作：无共享、无多人、无权限、无邀请
不做提醒：无通知、无推送、无日程提醒、无到期提醒
不做覆盖式导入：导入只做合并，不提供「用文件替换掉本地全部数据」那种模式
**不做云端自动同步**：本版不接任何同步服务、不自建服务器、不做定时上传拉取。相关设计已写好，见文末「后续版本」

## 验收标准
### P0：核心功能
首次打开：默认显示当天，四象限空状态渲染正常，无报错，生成本期用户数据 key
默认显示当天已有的数据；当天没有任何数据时，显示空四象限的渲染结果
拖拽：同象限排序与跨象限移动均生效，刷新后顺序保持；**移动端手指拖拽同样可用**
日期隔离：A 日期新增 / 修改任务不影响 B 日期
移动端：≤600px 单列展示，添加、勾选、编辑、删除、拖拽可用
数据互通：电脑导出 JSON → 手机导入 → 数据一致；反向同样成立。**整个过程不需要联网、不需要账号**
阶段：任务能展开 / 收起阶段列表（**默认收起**）；阶段的增删改勾选排序都生效，刷新后还在；**父任务的勾选 = 下面所有阶段一起勾上 / 一起取消**；有阶段时父任务的完成状态完全由阶段决定
任务块：每个象限右上角能创建任务块；任务拖进 / 拖出块都生效；块与块、块与任务混排拖动后刷新顺序保持；块跨象限拖动后块内任务一条不丢；勾块 = 块内任务全部勾上 / 取消；顶部统计和象限计数把块内任务算进去、块自身不重复计数；导出再导入块一条不丢；没有块的老备份照常导入
计划池：象限里的顶层任务能看到「推迟」选项；点击后任务从象限消失、出现在四象限下方的计划池里，刷新后仍在；池中任务可拖回任意象限（内容一条不丢，阶段跟着回去）；池中任务可删除；计划池任务不出现在顶部统计里；导出再导入计划池内容一条不丢；池内任务可设定 / 修改 / 清除完成时间，没设时间的任务一直留在池里；从象限推迟的任务打开池看到的时间是下一天；推迟阶段后，池里多出一条 `[所属任务]阶段文本` 的任务，原任务里这一条阶段消失；池头部「＋」能直接添加任务，新任务出现在池末尾、完成时间默认是当前查看日期的一周后，且同样可改可清
完成时段：无阶段任务行上能选六个时段之一、也能清除；有阶段任务的每个阶段行能各自选择、互不影响；任务本体有阶段时不出现时段选项；换时段 / 清时段不改勾选状态、顶部统计数字不动；导出再导入时段不丢；老备份（没有时段字段）照常导入
时间视图：能从四象限切到时间视图再切回，数据不变；设了时段的任务 / 阶段出现在对应时段组里，没设时段的不出现；只显示有任务的时段组且按从早到晚排序；阶段组内能看到所属任务标注；网页版（>600px）是 2 列（4 组时 2×2），手机端（≤600px）是单列；切换日期后时间视图显示新日期的分组；时间视图里勾选 / 编辑文字 / 删除 / 改时段都生效，切回四象限看到的结果一致（v1.2）；时间视图下计划池面板照常显示可用，模板面板不出现
模板：能把当天任务表缓存为模板（含块和阶段），模板出现在模板列表里、刷新后仍在；模板能重命名、能删除；应用模板后当天多出模板内容的副本（编号全新、勾选清零），再应用一次不会产生双份；未重命名时重新缓存同一天会覆盖原模板（内容更新、不新增条目）；重命名后重新缓存会新建一条；导出再导入模板不丢，同名模板导入时跳过
统计：顶部统计按「最细的可勾选单位」算 —— 有阶段数阶段，没阶段数任务自己（算法见 DS 2.9）
### P1：次要功能
导入导出：导出文件可下载且可重新导入；**合并导入后本地原有数据一条不少**；非法 JSON 被拒绝且原数据不变
勾选与统计：完成 / 取消完成后，顶部统计（已完成 / 总数 / 完成率）与勾选状态一致
本地体积：本地日期跨度超过 30 天时触发归档；**归档下载失败时本地数据保持不变**

## 边界情况
### P0：核心功能
空日期：无数据的日期返回四象限空数组，正常渲染空状态
空任务文本：trim 后为空则拒绝创建并提示
超长文本：允许换行完整显示，移动端不溢出、不截断
大量任务：单日 ≥200 条时渲染 / 保存仍可用，不允许卡死或丢数据
日期边界：跨年 / 跨月切换正确（YYYY-MM-DD 格式化，不出现 2026-13-01 类错误）
阶段边界：任务没有阶段时一切照常（它自己就是一个条目，统计里算 1 条）；把阶段全删光后父任务的状态保持不变，不会突然变回未完成；阶段只能在同一个任务内部排序，拖不出去
任务块边界：空块合法且显示占位提示，勾空块的勾选框无效果；往块里拖块不允许（按放到顶层处理）；删块连带块内任务一起删，提示要说清楚删了什么；块内任务的编辑 / 勾选 / 阶段操作与顶层任务行为完全一致；块改名输空文本拒绝并恢复原名
计划池边界：推迟一条已完成的任务照样进池（完成状态保留，不重置）；推迟带阶段的任务，阶段跟着进池；把池里最后一条拖回象限后，计划池显示空状态提示；空池不占版面关注（折叠为一条轻量区域）；往池里拖任务不允许（池只进得出：推迟进池 / 拖回象限，不接受从象限直接拖进池）；池中任务不参与任何日期的统计与归档；池内时间可以清除（清除后回到「未设定」，任务继续留在池里）；推迟的默认下一天按**被推迟任务所属的日期**算（查看过去的日期时推迟，不会得到一个已经过去的时间）；推迟父任务最后一条阶段后，父任务保持原来的完成状态不变（删光阶段状态停住的规矩，见阶段边界）；老备份（没有池内时间字段）导入后池内时间显示为空；池内手动添加时空文本安静取消（和象限新增同一条 D-31 规矩）；手动添加的默认 7 天基准是**当前查看的日期**（查看过去日期添加时，不会得到一个已经过去的时间，与推迟默认下一天同一个道理）
完成时段边界：时段只是标记——改时段不动完成状态、统计与象限计数一个数字都不变；块内任务能设时段、块本体不能；同一天任意多条任务选同一个时段互不影响（时段不是唯一键，时间视图允许一个时段下有多条）；数据里的时段值不在六个之内时，读入丢字段保任务（与池内时间同一条规矩，见计划池边界）；保护模式下时段不可改
时间视图边界：当天一条设了时段的任务都没有时显示空状态提示（不是空白页）；同一时段下有多条任务时全部列出；切到时间视图后切换日期，显示跟着换；计划池任务不进时间视图的分组（池不按日期分），但计划池面板在时间视图下照常显示、照常可用；时间视图里勾选 / 编辑 / 删除 / 改时段与四象限同效（同一份数据），改时段后条目挪到新时段组（清除时段则离开时间视图）；时间视图不提供新增和拖拽（结构操作回四象限做）
模板边界：缓存空的一天 → 拒绝并提示（没有内容的模板没有意义）；应用模板到已有任务的日期：同象限同文本的条目跳过、其余照加，当天原有任务一条不动；模板里的勾选状态在应用时清零（模板是计划不是记录）；重新缓存覆盖只发生在「自动名未被用户改过」时；删除模板不影响任何日期的任务（模板是副本，不是引用）；老备份（没有 templates 字段）照常导入；保护模式下缓存 / 改名 / 删除 / 应用全部禁止
数据兼容：**加阶段之前导出的 JSON 必须还能正常导入**，一条任务都不能丢（老备份里没有阶段字段，这属于正常情况，不是格式错误）
首次启动无任何数据：正常初始化，不报错，且**不弹「从备份恢复」的提示**
数据损坏：主数据读不出来时按备份顺序恢复；**全部读不出来时进入保护模式**——禁止一切写操作、磁盘上的原始数据一个字节不动，由用户选择导入备份文件或重新开始
### P1：次要功能
非法导入：JSON 解析失败或结构不符（非对象、缺象限键）→ 拒绝导入，保留现有数据，给出错误提示
导入误操作：导入前二次确认，并提示「建议先导出备份」
历史数据：本地超过 30 天的数据归档后会从本地移除，用户需要导入归档文件才能查看

## 后续版本：云端同步（v1.0 不做）

**本节内容本版全部不实现。** 完整设计见 `DS.md` 第六章，以下只列需求口径。

原先规划的是「变更后 3 秒内写入同步容器」——所有设备读写坚果云上的同一个 JSON 文件，网页版和 App 端自动保持一致。

**为什么移出 v1**：它是整条链路上唯一依赖外部服务的环节。实测确认坚果云没有开放跨域响应头，网页端连不上（详见 DS 6.3），要连上就必须自建一台 CORS 中转代理，进而需要买服务器 + 域名 + ICP 备案（1~3 周）。把这块摘掉，v1 就变成一个完全不依赖网络和第三方服务的纯前端应用。

**将来做的时候，需求是这些**：

- 云端自动同步：变更后 3 秒内上传；打开程序时拉取并与本地**合并**（不是覆盖）
- 安卓端直连坚果云；**网页端必须经自建中转代理**
- 代理**无状态**——只转发请求，不存用户数据、不碰用户密码
- 同步失败**绝不能影响本地使用**；数据来源可疑时（刚从备份恢复、保护模式中、读取出错）**暂停自动上传**
- 「访问口令」只是一个自用的共享密钥，**不构成账号体系**——服务端不据此识别任何用户，也不保存任何用户数据
- 已知限制：删除操作不保证跨设备同步（合并只增不减）

**验收口径（届时适用）**：

- 电脑改完 → 手机打开能看到；两台设备各改各的 → 两边都打开一遍 → 两边的改动都在
- **断网时改数据 → 关掉 → 联网后再打开：本地的改动必须还在**
- 代理停掉时网页版降级为「同步暂时不可用」，本地数据完好、不报错、不丢数据
- 数据处于异常状态时**不自动上传**，要用户手动确认
