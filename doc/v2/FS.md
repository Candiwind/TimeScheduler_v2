## 背景与目标
第一版把闭环跑通了：能建任务、能拖、能存、能备份。但它只能记「一行字」，记不下现实里的任务——一个任务往往要拆几步走，一件大事要横跨几周，一堆想法要有个地方先放着。

**这一版的目标是把「记下来」变成「管得住」**，具体三件事：

- **任务能拆**：任务、任务块、子任务、阶段四级结构，完成度自动往上汇总
- **时间有去处**：今天的进四象限，以后的进计划池，长线的进大任务，零碎的进笔记池
- **做错了能回头**：删除、完成都先进回收站；每天的数据可存快照；导入缓存可按星期自动带出来

工程上延续第一版的分层模块化，不推倒重来。

## 功能列表

### P0：核心功能

#### 一、任务结构
任务由「一行字」扩展为四级：**任务 → 任务块 → 子任务 → 阶段**。任意一级都可以是终点，不必四级齐全。

- **阶段拆分**：任务、子任务、计划池任务、笔记都能拆成多个阶段。每个阶段与自己拆出来的那一级**等权重**，有独立的文本、完成勾选、时段；阶段自己独立的 checkbox，全完成时父级自动完成
- **任务块**：一个块下挂若干子任务，块头显示完成度；子任务可排序、可拖出块、块可跨象限迁移
- **时段**：每一项（任务 / 子任务 / 阶段）都带时段：早晨 / 上午 / 中午 / 下午 / 傍晚 / 晚上。新建时按当前时间自动给默认值，**不允许出现「无时段要求」这一分类**
- **Bonus 任务**：任务、阶段可以标记为 Bonus，图标用礼品（🎁）。计算完成率时 Bonus 是**额外加分**项：分母不计入 Bonus，分子计入，所以完成率允许超过 100%。任务全为 Bonus 时，完成率按已完成 Bonus / 全部 Bonus 计算；一个普通项都没有的组视为未完成（不显示 0%）
  - **「全完成」与完成率是两条口径**（v2.5）：打勾样式、完成沉底、派生 `completed` 走的是「全完成」——**每个阶段 / 每个子任务都做完**才算，Bonus 没做完就不算全完成；Bonus 只影响完成率的分母，不影响这个判断
- **排序规则**：一律「未完成在前、已完成在后」；同一组内按时段排，并保留用户手拖的顺序（稳定排序）
- **完成沉底**：任务（含任务块内的子任务）勾选完成后自动排到同组最后；**阶段不沉底**，始终按原顺序排，需要调整由用户手动拖。取消勾选不自动移回原位
- **折叠**：有阶段的条目、有子任务的块，都能折叠/展开，折叠状态记在本机，刷新后保持
- **模块折叠**：大任务、计划池、依循等面板默认收起；在面板内做子操作不应把已展开的面板重新关上

#### 二、大任务规划
管那些横跨多天、需要拆解的事。同时最多 5 个**未完成**的大任务——完成一个就腾出一个名额。

- 大任务 → 里程碑 → 子任务 → 阶段，四级增删改
- **进度自动计算**：按叶节点算（有阶段算阶段，没阶段算子任务），子项勾选后逐级往上报
- **手动完成**：除了子项全完成自动完成，也提供「完成」按钮直接标记
- **每日任务量提醒**：某天的子任务超过 3 条时给出提示
- **子任务带日期**：给子任务安排到某天，到那天可一键带进今天的象限
- **导入**：右侧「导入今日任务池」按钮（不用展开卡片就能点到）单个子任务导入；带阶段的子任务连同阶段一起复制
- **不重复导入**：导入过的记录引用关系，已导入的自动跳过；删除或移走后不会又被自动带回来
- **推迟**：整张卡片推迟，截止日期顺延一天
- **完成后**：现存数量按未完成计；显示逾期完成天数（超期完成 N 天）；自动归档进大任务缓存库，需要时可以恢复回活跃列表

#### 三、计划池
管「还没到那一天」的事。分三个池，用 Tab 切换：**待办 / 本周 / 本月**。

- 每个池里能放任务、任务块、子任务、阶段，都能拆阶段
- **勾选完成**：池里的任务可以直接勾完成，文字划掉变淡，但**不移出池**（要移出由回收站规则决定）；完成后自动沉到**它所在的那个列表**（池顶层 / 所在块内）的末尾，取消勾选不自动移回（v2.7 补齐沉底）
- **池内任务块与象限任务块同格式同功能**（v2.7）：块头 = **勾选框（一键全勾 / 全取消块内）+ 块名（点击改名）+ 完成度 n/m** + 折叠三角 + 动作按钮；块内每条任务有勾选框、点文字改名、删除，外加池独有的完成时间（DDL）。**唯一保留的差异**：池内块头的动作按钮是「导入」而不是「推迟」——池本身就是推迟的目的地；象限块头有「推迟」是因为那边才是任务的所在地
- **拖入象限**：池里的任务和任务块都能直接拖进四象限（块内任务拖出去 = 从块里摘出来，宿主块完成度重算）
- **池内拖拽排序**（v2.6）：池内条目可以拖拽换顺序——顶部条目之间换、同一条任务块内的任务之间换；**各自列表内排，不跨容器**（不把顶层任务拖进块、也不把块内任务拖回顶层）
- **按计划日期自动导入**（v2.6 改写）：**真实今天** ≥ 计划日期的顶层池条目，在启动 / 切换日期时自动**移入今天**的第二象限。任务块本身不设计划日期（见 v2.2 需求 4），取块内任务里**最早**的那个计划日期判断
- **立刻导入**（v2.6 改写）：每条池条目行上有一个「导入」按钮（块头上也有），一键把这条（含全部阶段 / 整块连块内任务）**移入当前查看日期**的第二象限。**是移动不是复制** —— 池里不再保留；要退回池里再用「推迟」或拖回
- 池里没有任务时自动收起，有任务时自动展开

#### 四、时间视图（按完成时段看）
除了按「重要 / 紧急」看，还能按「什么时候做」看。

- 象限视图 ⇄ 时段视图一键切换，偏好记在本机
- 按六个时段分组，组内按 I → II → III → IV 排
- **层级不能丢**：父条目（块 / 带阶段的任务）在它子项所在的时段里以分组标题出现，子项缩进显示；子项跑到别的时段时，用「↳ 子任务名」标注它属于谁
- **网格布局**：1 个时段 1 列；2 个以上时段一行两个（3 个时段 → 2+1，6 个时段 → 2×3）；手机端强制单列
- 任务按所属象限带浅色背景（一 / 二 / 三 / 四象限各一种浅色）；已完成保留背景只把文字划掉
- 每个时段块自己滚动，互不牵连；整个时段块有最大高度，超出在右侧出滚动条
- **可拖拽排序**：时段视图里可以拖拽条目调整顺序，也可以跨时段拖拽（顺带改掉它的时段）；拖拽后的顺序**按天记住**，切日期、刷新、切视图后再回来仍保持
- **新任务排最前**（v2.5）：在象限视图里新增的任务（同一时段）、以及刚设上时段的条目，出现在该时段时间视图列表的**最前**——和象限视图「新增任务加在开头」是同一条规矩；已在记忆里的那些条目之间仍按拖拽记忆排，优先于默认的 I → II → III → IV 扫描顺序
- **结构保持只读**：时段视图里能改文字、改时段、勾完成、删除、推迟、拖拽排序，但不能新增子任务或阶段——避免在时段视角下把结构改乱
- 时段块上显示该时段的条目数，计数不重复计算父子项

#### 五、缓存与回收站
这一版最重要的安全网：**删了、完成了，都还能找回来。**

- **回收站**：大任务 / 里程碑 / 子任务 / 阶段、依循原则、优先问题、计划池三个池，各自独立回收站
- 每条回收站条目带**时间戳**，支持 **置顶保护**（置顶的不会被挤掉）、**恢复**、**永久删除**
- 恢复时先检查原来的父级还在不在；父级没了就明确拒绝，**不允许静默丢数据**
- 回收站有**数量上限**，满了先挤掉最旧的、没被置顶的那条；全都置顶时拒绝添加并提示
- 条目能**展开看详情**（Markdown 形式），不用恢复出来才知道是什么
- 回收站默认收起，展开状态记在本机

- **数据快照缓存（导入缓存）**：把某一天的数据**整份存下来**，之后可以带到别的日期
  - 同一个日期可以有**多份快照**，互不覆盖
  - 每条快照可**重命名**、可**导出单日 JSON**、可**删除**、可**置顶**
  - 只在用户主动点「缓存」时才产生快照——**当天数据不会自动堆进缓存库**
  - 导入时按 `id` 去重合并，导入后不关弹窗，方便连着导好几条
  - **自动导入**：置顶的快照可以按星期配置自动导入——工作日 / 周六 / 周日三个开关，到点自动带出来，不用手动点

#### 六、统计与日报
- **首行完成情况**：`✅ 已完成 / 总数 · 完成率`，一行看完
- **象限右上角**：显示本象限 `已完成 / 总数 完成率`，不再是任务总数
- **任务占比**：所有任务权重均等，单项占比 = 100 ÷ 任务总数；全部完成时加起来正好 100%。**废弃第一版的象限固定权重**
- **Bonus 口径**：分母只计非 Bonus 项，分子计全部已完成项（含 Bonus），所以完成率可以超过 100%；全 Bonus 时完成率按「已完成 Bonus / 全部 Bonus」算
- **分时段完成情况**：早晨 + 上午 / 中午 + 下午 / 傍晚 + 晚上三组统计
- **最近完成情况**：显示最近几天的完成情况
- **日报生成**：预览 + 复制 + 下载，Markdown 和 HTML 两种；内容要包含**待办池 / 周计划 / 月计划**里的任务，不只是象限里的
- **日报自动统计**：导出的日报（Markdown / PDF）里，每个日期标题下方自动加入一行当日统计：`已完成 X / 总数 Y · 完成率 Z%`；有 Bonus 时补一句「含 Bonus B/C」，Bonus 项用 🎁 标记
- **Markdown 日报只记当天**（v2.6）：导出的 Markdown 只包含**当前查看的那一天**（日期栏选中哪天就导哪天），不再一次导出全部日期。JSON / ZIP 仍是**整份存档**，保证导出后能重新导入还原
- 统计口径改动必须**同时**改渲染、统计面板、日报三处，不允许出现三处对不上

首行信息密度要控住：任务数到三位数时首行不换行（字号分主次，主统计大、次统计小）

#### 七、推迟与标记
- **推迟**：把今天做不完的推到计划池，记录推迟次数
- **推迟备注**：显示「推迟 N / 共 M 条」；**推迟计数每天清零重新统计**，不累计成历史包袱
- **未完成推迟**：明确标记「今天确定没做」，任务**留在原位**并打叉，同时把副本推进计划池；可以取消标记，取消后副本一并撤掉
- **额外完成**：标记今天额外做的任务，不计入当天计划
- **任务带阶段整体推迟**：拆了阶段的任务和任务块也能整体推，阶段数据跟着走，迁回时自动恢复
- **高亮**：鼠标划选文字 + `Ctrl+Q` 或右键，把重点片段标出来；**任务完成后高亮自动失效**；暗色模式下高亮是纯色覆盖整个字高，文字必须看得清

  **v2.9 起另加「整条高亮」**（见「二十二」）：不用划选，**连续双击**任务 / 任务块 / 阶段就把整条标成浅橙底。两者是**各自独立的两件事**——片段高亮标记的是划选出来的几个字，整条高亮落在这一条数据自己的 `highlight` 字段上；**「任务完成后高亮自动失效」是同一条规矩**，两种高亮都只在未完成时显色，数据字段都留着不动（取消勾选后自己回来）。

#### 八、批量删除
象限、计划池、大任务三个区域都能进「批次模式」：

- 每行左边出现选择框，底部出现操作栏（全选 / 反选 / 删除 / 取消）
- 支持批量删任务、任务块、子任务、阶段
- 批量删除同样走回收站，不是物理删除
- 切换视图、切面板、换日期时自动退出批次模式

#### 九、数据互通（手动）
**这一版仍然不做云端同步**（见「非目标」）。跨设备还是走「导出 → 导入」：

- 电脑端导出时给出**可复制的 JSON 文本**，不用传文件，直接发过去粘贴
- 手机端导入支持**文件选择**和**粘贴 JSON** 两条路，粘贴时可选择合并或覆盖
- 安卓端导出时同时写两份：带日期的文件名，和固定名字的同步文件；下次启动时从固定名字那份检测导入
- 导入后自动刷新全部视图，不用手动刷新页面

### P1：次要功能

#### 十、依循与阅读
- **依循**：设置起止日期，放 1~5 条原则（建议不超过 3 条）
- **优先问题**：依循下挂「最近优先解决的问题」，最多 2 条（建议 1 条）
- **阅读**：在读 / 待读两个列表，每本可设开始与结束日期；在读的书可一键**标记已读完**（自动写入当天为结束日期，支持撤销）；收起时显示 `(已读完 / 在读 / 在读+待读)` 计数

#### 十一、笔记池
零碎想法的暂存区，绿色主题区分。

- 添加、编辑、删除、勾选完成，**同样可以划分阶段**
- 单个笔记或全部阶段可导入今天的 Q-II
- 未拆阶段的任务、计划池任务、块内子任务，都能「添加到笔记池」
- 面板默认收起

#### 十二、PWA 与移动端
- **Service Worker**：预缓存核心资源（某一个文件失败不影响其余）、升级时清掉旧缓存、立即接管、HTML 走后台更新、离线时给中文离线提示页、检测到新版本时提示用户
- **manifest**：补全作用域、显示模式、分类、截图、快捷方式等字段，提升各浏览器「添加到桌面」的兼容性
- **meta**：补齐 iOS / 安卓各浏览器的状态栏、图标、缩放等标签
- **触摸目标**：手机端所有可点元素不小于 48px
- **手机端排版**：一行放不下时自动折行——文字独占第一行（占满整行宽度、允许换行完整显示），操作按钮折到第二行（**按各自原宽排布，不拉伸、不均分**）。这条 v2.1 起就在，v2.10 需求 4 把它落到实现上并改定「不均分宽度」的口径，见「二十六」
- **手机端源码编辑器**：HTML / CSS / JS 三个 tab，预览与编辑一键切换，本地自动保存，可导出完整 HTML，可重置回原始代码

#### 十三、数据安全与性能
- **滚动备份**：保留多份快照，恢复时从新到旧依次尝试；某一份坏了不会连累其余
- **schema 版本号**：给未来的数据结构变更留锚点，不写死「当前就是最终格式」
- **配额检测**：存储写不下时估算占用并给出具体清理建议（比如「导出 JSON 后清理历史日期」），而不是一句通用报错
- **内存缓存**：读数据命中缓存时不再重复解析
- **渲染防抖**：连续操作合并为一次渲染
- **统计合并遍历**：一次遍历同时算出象限、占比、时段三组指标
- **启动延迟**：迁移、种子数据、归档等一次性任务延后执行，不拖慢首屏
- **可访问性**：所有可编辑文本、可折叠面板标题、可展开卡片都要有键盘焦点样式

#### 十六、搜索（v2.4）
对应 `requirements.txt` 第 3 条：

- **搜索入口在整个界面右上角**（顶栏动作区）：🔍 按钮点开输入框，再点一下或按 Esc 收起
- **象限模式**：按关键词过滤四个象限——只显示含关键词的任务，没命中的象限显示空白。命中看任务文字、阶段文字、块名；块名命中整块显示，只有子任务命中时块里只显示命中的子任务
- **时间模式**：按关键词过滤各时段块——时段块保留，没命中的时段块显示空白，命中的时段块只显示匹配的条目（阶段条目还能按所属任务名命中）
- **只过滤显示、不动数据**：搜索是「画的时候少画」，任务本身一条不删；收起搜索后完整内容原样回来
- 关键词大小写不敏感、前后空白自动忽略；输入时实时过滤
- 计划池、模板池不参与过滤（搜索针对的是「当天的任务」）

### 十七、计划池四条（v2.6）
对应 `requirements.txt` 第 1~4 条：

1. **池内拖拽改顺序**：池内条目（顶部任务、顶部任务块、块内任务）都能拖拽换顺序，落点用和象限一样的中点翻位规则。**只在各自列表内排**：顶部条目之间互为落点，同一条块内的任务之间互为落点；拖到别的池列表、或拖到象限以外的空白处，不改任何数据。
2. **导入默认落在第二象限**：池条目行上（块头上也有）有「导入」按钮，一键导入**当前查看日期**的 Q-II。语义是**移动**（和拖回象限一致）：条目从池里消失、出现在 Q-II 列表**开头**（和象限「新增任务加在开头」同一条规矩）。含阶段的任务连阶段一起搬；块连块内任务整块搬；块内任务单独导入时从块里摘出，宿主块完成度重算。
3. **计划日期到了自动导入**：启动时、以及每次切换日期时检查一次——**真实今天** ≥ `plannedDate` 的顶层池条目自动移入**今天**的 Q-II（同样加在开头）。任务块没有 `plannedDate`，取块内任务里最早的计划日期判断，整块一起回来（不拆散）。导入后池里不再保留，同一条不会重复导入。查看历史上的某一天**不会**触发（避免「往前翻一眼，任务就被搬走」）。
4. **Markdown 日报只记当天**：导出的 Markdown 只含当前查看的那一天，文件名带上那天的日期。JSON / ZIP 保持整份导出不变。

### 十九、阅读栏（v2.8 需求 2）
一个记录「最近在读什么」的小板块，整块**排在四个象限上面**（顶部）。

- **正在阅读**：右上角「＋」加一条，写书名 / 事项名；每条可以**自己设起始日期**。
- **提示不超过 3 项**：头部显示 `n/3` 计数，超过 3 项时计数标红并给一句「建议不超过 3 项」的说明。**提示不是硬闸**——第 4 条、第 5 条照样加得进去，只是把数字标出来提醒一下。
- **时间记的是日期**（v2.8 补充）：起始、完成都是**哪一天**（`YYYY-MM-DD`），不记几点几分。新增时默认**今天**，勾完成自动记**今天**；日期可以自己改，也可以清成「未设定」。
- **改起始日期的方式和计划池的完成时间一模一样**（v2.8 补充）：行上的日期本身就是按钮，点一下原地换成日期框，「回车」或「点到别处」提交，旁边的「清除」把日期清成「未设定」（条目不会被删掉）。没设过时按钮显示灰色的斜体「未设定」，和池里同一个长相。
- **勾完成**：条目前的勾选框一勾，这一条就从「正在阅读」搬到下方**已读完成**，并**自动记下完成日期**。行上显示「起始日期 → 完成日期」；**同一天开始同一天读完就只显示一个日期**（不画「X → X」这种废信息）。
- **已读完成**：另有一段列表，头部报个数。这里可以**自己改起始日期**（需求明说了下方也要能改，所以那一行上的日期同样是点得动的按钮，和正在阅读那边一个样），也可以**取消完成**（点行首的「↩」把它放回正在阅读，是给点错了留的退路）。
- **展示上限**：已读完成那段有最大高度，条数多了**在列表里滚动**查看，**不截断、不丢数据**。
- 正在阅读的条目同样支持：改名（点文字）、改起始日期（点日期）、删除（行尾「×」）。
- 阅读栏是**逐条独立的清单**，不参与每天的日期切换、不计入统计 / 完成率、不进 Markdown 日报；但它属于用户数据——**JSON 导出 / 导入会带上它**，且**导出文件兼容以前所有版本**（老版本文件里没有这个字段，照样能导入）。

### 二十、板块收起（v2.8 需求 3）
阅读栏、计划池、模板池三个板块的头部最左边都有一个收起三角（▾）。

- 点一下收起，只留头部一行；再点一下展开。收起是**纯界面动作**，不发任何写操作（保护模式下照常能点）。
- **收起状态记在本机**（和已有的折叠 / 展开状态同一份存储），**刷新页面后保持**。

### 二十一、计划池任务块的外框对齐象限（v2.8 补充需求）
计划池里的任务块在格式和功能上已经和象限里的块一致（v2.7），但**外框还不是**：象限里的块是一圈浅蓝底 + 蓝色左边框的圆角盒子，池内块只有一条灰竖线。本版把池内块换成同一个外框：

- 浅蓝底（`--q2` 的 4% 混色）+ 完整 1px 边框 + **3px 蓝色左边框**（`--q2`，就是象限 II 的蓝）+ 6px 圆角；
- 块名、完成度、勾选框、折叠三角、动作按钮（池内是「导入」）的**内部排版不变**；
- 块内任务的缩进仍用池自己的值（池面板比象限窄，照搬象限的 30px 会把内容挤出可视区）。

### 二十二、连续双击整条高亮（v2.9 需求）
对应 `requirements.txt` 第 1 条：**连续双击**给当前任务 / 任务块 / **阶段**的**整体**加上高亮效果；高亮用**浅橙色**，**完全覆盖字体的高度**。

- **手势**：在同一行上**连续点两下**（第二下落在双击判定窗口内）就是「整条高亮」的一次开关。**点一下照旧是原来那件事**（点文字进编辑、点勾选框勾完成、点按钮触发按钮）——高亮不抢单击，只在第二下时动手。已经开着的编辑框会被先落下（等于双击时自动提交），再切换高亮，不会把正在输入的内容丢掉。
- **能高亮的三种对象**：任务、任务块（象限里的块 / 池里的块）、任务里的**阶段**。**能高亮的地点**：四象限、时间视图、计划池——池里的任务和池里的块也算（它们和象限里的同一条数据，两边一起变）。
- **开关**：再连续双击一次就取消高亮；高亮落在数据里（那条自己的 `highlight` 字段），不是界面上的临时状态，切视图 / 刷新 / 切日期回来都还在。
- **浅橙色 + 盖满字高**：底色是**浅橙**（`#ffd8a8` 一类的浅橙），画在文字**内容行**上——背景高度跟着行高走（1.6em），**完整盖住字的上下**，不是只垫在字后面的一条窄带。为了不把旁边的字挤开，这层底色左右各外扩 3px（用负边距抵掉），行与行的对齐不变。
- **字要看得清**：底色浅，文字颜色是**固定**的深棕（不跟随主题、也不跟随象限底色），保证浅橙底上的对比度够（≥ 4.5:1）。**暗色主题下也不覆盖**这层底色与文字色——「纯色覆盖整个字高」这条要求两端一致。
- **完成后自动失效**：这一条**做完了**（任务 / 阶段勾完，或块整体完成）就不显色，恢复正常样式；**数据里的 `highlight` 不动**，取消勾选后高亮自己回来。和「七、推迟与标记」里片段高亮是同一条口径。
- **不参与统计**：高亮**不是完成**、不影响完成率、不影响 Bonus 口径、不改排序、不改 DDL，也不触发任何自动导入 —— 它是一个纯标记。
- **不传染**：给任务块加整条高亮**不会**把块里的任务一起标上（块头标橙只是「这块先看着」）；给任务加也不会传递给它的阶段。每条各标各的。
- **随手带得走**：推迟 / 复制 / 模板套用时高亮跟着走 —— 任务推迟进池、阶段推迟（连同它包出来的池条目）、任务块整体推迟、按计划日期自动导入、拖回象限、从池里「导入」都保留原条的高亮；筛选（搜索）留下的副本同样保留。
- **导出 / 导入**：`highlight` 随 JSON 一起导出；导入时只有**严格是 `true`** 才算高亮（`false` / `"yes"` / `1` / `null` / 空对象都按「没高亮」处理，脏值不落库、整份导入照样成功）。**兼容以前所有版本**：老文件里没有这个字段，读进来就是「没高亮」，不补默认值；旧版本读 v2.9 导出的文件也会忽略这个不认识的字段。
- **保护模式**：高亮是写操作，保护模式下双击**点不动**，数据一个字节不动。
- **边界手势**：拖拽刚结束那一下的「残留点击」不应误伤 —— 记录下来的落点带时间戳，超过双击窗口就当过期丢弃，宁可「什么都不发生」，也不去标错一行。

### 二十三、勾选完成不弹回顶部（v2.10 需求 1）

对应 `requirements.txt` 第 1 条：在各个象限、以及时间视图下的各个时间栏里，**出现滚动条之后**，点任务的完成 / 未完成勾选框，**页面不得自动滚回最顶部**，要停在原来的位置。

- **管哪些地方**：四象限各自的列表、时间视图的**每一个时间栏**、**计划池**（含池内块内的任务）、模板池、阅读栏（含「已读完成」那半边）—— 页面上每一个能纵向滚动的容器都在内。
- **管哪些动作**：勾任务完成 / 取消完成、勾阶段完成 / 取消完成、勾任务块头（一键全勾 / 全取消）、勾池内条目和池内块头。这些都是**原地改一个字段**，列表长度和条目位置都没变，用户的视角没有理由被重置。
- **不管哪些动作**：新增、删除、推迟、导入、切日期、切视图、改搜索词 —— 这些操作**列表内容真的变了**，画完从头看才是对的（新增任务还加在最前面），保留旧位置反而像「没生效」。
- **滚多远就停多远**：每个容器各记各的，互不牵连（第二象限滚到中间、第一象限停在顶部，勾完还是这样）。时间视图里每个时间栏也是各记各的。
- **实现口径**：渲染层只负责「拍快照 / 贴回快照」两个动作，什么时候用由入口层决定（见 DS 2.41）。

### 二十四、手机端拖动把手 = 勾选框（v2.10 需求 2）

对应 `requirements.txt` 第 2 条：手机端**象限模式和计划池中所有任务 / 阶段**的拖拽，都要以**完成勾选框所在的位置**为拖动 handle；**其他位置触碰到之后不应该触发拖动效果**。

- **把手统一到勾选框**：任务、阶段、任务块（象限里的和池里的）都一样 —— 触摸端按住勾选框就是「拖起来」，按住别处不动，那一处留给页面滚动。
- **池里从此也有了把手**：这是本版改定的口径。v2.1 给象限里的任务定了「勾选框是把手」，但池里的勾选框当时**只做勾选、不当把手**（池条目整条可拖），代价是**池列表在手机上根本滚不动** —— 手指一按就被判成拖拽（DS R-33 记的就是这条）。现在池和象限一视同仁，那条限制随之解除。
- **勾选框仍然只是勾选框**：轻点一下照旧是勾选 / 取消勾选，不会因为「松手时没挪动」而变成别的事；拖动要有明确的位移（超过起拖阈值）才成立。
- **鼠标端不变**：鼠标仍然整行、整块头都能起拖（宽屏上手指精度不是问题，行内任何位置起拖更省事）。
- **笔（stylus）跟手**：和触摸同一条规则。
- **不在名单里的东西**：勾选框、删除键、推迟键、时段下拉、Bonus 开关、导入键、加阶段键、折叠三角、编辑输入框 —— 按这些永远不进入拖拽（鼠标也一样）。

### 二十五、象限 ↔ 计划池双向拖拽（v2.10 需求 3）

对应 `requirements.txt` 第 3 条，原话是「**象限中所有可能的拖动情况，在计划池中都需要相应支持，相互之间的拖动都需要支持**」。两条点名的场景是：

1. **象限的任务 → 计划池的任务块**（拖进池里某个块内，成为它的子任务）；
2. **象限的任务 → 计划池的任务**（拖到池顶层的某个位置）。

落点一共这些，全部受理：

| 拖什么 | 落在哪里 | 结果 |
|---|---|---|
| 象限任务 | 池顶层任意位置 | 从象限摘出，插到该位置；完成时间默认设为**所属日期 + 1 天**（和「推迟」同一条） |
| 象限任务 | 池内某个任务块 | 同上，插到块内该位置；宿主块完成度重算 |
| 象限任务块 | 池顶层任意位置 | **整块**原样搬进池（不拆散）；块内每条任务完成时间 +1 天，块本体不设 |
| 池内任务 | 象限顶层任意位置 | 从池摘出、按占位符落位；**不再**默认回第二象限 —— 拖到哪就是哪 |
| 池内任务 | 象限的某个任务块 | 落进块内该位置；目标块完成度重算 |
| 池内任务 | 池顶层 ↔ 池内块（互相） | 池内的跨容器搬运，两端宿主块完成度都重算 |
| 池内任务块 | 池顶层 / 象限顶层 | 只落**顶层**（块里不许套块，见下） |

- **块只能落顶层**：任务块**不能**被拖进任何块里（象限的块、池里的块都不行），也不能拖进它自己 —— 「块里不许套块」是全局规矩，两个区域一致。
- **象限里有的，池里都有**：象限支持「任务进块 / 任务出块 / 顶层换位 / 跨象限搬运」，池里对应地支持「任务进池块 / 任务出池块 / 池顶层换位 / 池顶层与块内互相搬运」。这是本版真正的新能力：v2.6 的池内拖拽**只允许在各自列表内排序**（顶层只和顶层排、同一块内只和同一块内排，跨容器一律不受理）。
- **落点怎么算**：以**指针底下**那一个列表为准（顶层或块内），和来源无关；落点算出的位次口径与象限一致 —— 以「把这条摘出来之后」的列表为准，越界自动夹紧。
- **失败不猜**：找不到的 id、非法的日期、把块拖进块 → 拒绝，**数据一个字节不动**（界面上表现为保持上一次的落点，松手后什么也不发生）。
- **两区通用的连带效果**：搬进 / 搬出会改变宿主块的完成度（块内任务数变了）；把某一天最后一个象限条目拖进池之后，那一天会被收掉（不留空壳日期，和「推迟」同一条）；任务搬到池里时**完成时间默认设为所属日期 + 1 天**（和「推迟」一致）；搬的是同一个对象，文字、完成状态、阶段、高亮、Bonus 全都原样带着走。
- **保护模式下不许拖**：和既有的拖拽一样，保护模式下一个字节都不动。

### 二十六、手机端排版优化（v2.10 需求 4）

对应 `requirements.txt` 第 4 条，两条：

1. **按钮折行**：手机端每个任务 / 阶段右侧有一串操作按钮，**左侧文字长度超过操作按钮区域时，把操作按钮移到下一行**；
2. **文字占满整行宽度，并自动换行**。

- **怎么折**：一行装不下「勾选框 + 整段文字 + 这串按钮」时，整串按钮一起折到第二行，文字在第一行占满剩余宽度并自动换行、完整显示（不截断、不省略号）。
- **不是「永远折」**：文字短的行（加上按钮仍然放得下一行）**照旧是一行**，不会平白多出一条空白。判据就是整段文字的实际宽度够不够塞下。
- **折下来的按钮按各自原宽排布**，不拉伸、不均分宽度 —— 一排「＋」「×」「🎁」被拉成等宽的粗块既难看又难认（这条把 v2.1 里「均分宽度」的说法改掉了）。
- **覆盖范围**：任务行、阶段行、任务块头（象限的块头和池里的块头），以及**复用同一套行结构**的时间视图条目和计划池条目 —— 两边不用各写一套。
- **桌面端不受影响**：这些都是「手机端」（`max-width: 600px`）的规则，宽屏上一行放得下，排版照旧。

> **v2.11 修订**：上面「整串按钮一起折到第二行」这句，v2.10 其实**没做到** —— 那时是每个控件各自参与折行，会出现「一半按钮留在第一行、一半掉下去、且都靠左」，长文还会**连文字一起**掉到第二行、第一行只剩一个勾选框。折行后的对齐也从「第二行最左」改成「靠右对齐、左侧留空」。据此重写为二十七。

### 二十七、手机端折行的两处收尾（v2.11 需求 1、2）

对应 `requirements.txt` 最前面的两条（v2.10 之后补充），都是**手机端排版**的收尾：

1. **文字换行时把第一行勾选框右侧的空间用上**：文字长到要换行时，文字应当**紧挨着勾选框**从第一行开始排、并在第一行占满剩余宽度后自己换行；**不许**整段文字被挤到第二行、让第一行只剩一个勾选框和一大片空白。
2. **右侧按键的显示规则**：
   - 空间够 → 所有按键完整显示在这一行的右侧；
   - 空间不够 → 按键**整组**另起一行，放在下一行的**靠右对齐**位置，左侧预留空白。

- **「整组」是硬要求**：那串按键是一个整体，装不下就**整组**折到下一行，不会「前三个留在第一行、后两个掉下去」。为此在渲染层把文字右边那一串控件（完成度 / 折叠三角 / 时段下拉 / 🎁 / ＋ / 推迟 / 删除…）包进一个组（`<span class="task__actions">`）。
- **不是「永远折」**：文字短、加上按键仍然放得下时**照旧是一行**，按键还是显示在这一行右侧，不会平白多出一条空白。判据仍是整段文字的实际宽度够不够。
- **折下来的按键按各自原宽排布**，不拉伸、不均分宽度（沿用二十六的口径）。
- **覆盖范围**：任务行、阶段行、任务块头（象限的块头、池里的块头）、时间视图条目、计划池条目 —— 和二十六同一批，共七类行。模板池条目与阅读栏条目不在内（它们不是「任务」）。
- **桌面端不受影响**：以上全部只在「手机端」（`max-width: 600px`）生效；宽屏上那层包裹是透明的（`display: contents`），不生成盒子、间距与对齐和加它之前完全一致。
- **APK 与网页版一致**：纯 CSS + 一点点渲染层包裹，两端同一份代码，没有差异（见「网页版与 APK 差异点（v2.11）」）。

### 非功能需求
- **纯原生实现**：HTML / CSS / JS，页面运行时不引第三方库、无构建步骤；沿用 var + IIFE 风格（兼容 Capacitor WebView 与 file:// 场景）。Capacitor 及其插件属**构建期依赖**，不受此限

- **离线可用**：断网状态下增删改查、导出、导入、缓存、归档全部正常

- **打包**：可经 Capacitor 打包为安卓 App
- **测试**：新增或修改核心逻辑时必须补本地回归测试，覆盖正常路径、边界和错误路径；已通过的测试不允许因为新功能回退

### 非目标（本期明确不做）
给后续开发者（含 Claude Code）的硬约束：任何超出以下边界的功能需求一律拒绝或移入后续迭代，不得自行添加。

- **不做提醒**：无通知、无推送、无日程提醒、无到期提醒
- **不做服务端**：不写后端、不买服务器、不备案

## 网页版与 APK 差异点（v2.1）

v2.1 的大多数行为网页版与 APK 一致，只有以下几点不同：

| 需求 | 网页版 | APK（安卓） |
|---|---|---|
| **面板最大高度**（象限 / 时段块 / 计划池 / 模板池） | 电脑端用较大高度（象限 60vh、时段块 60vh、计划池 / 模板池 40vh），超出在右侧出滚动条 | 同样的规则，但手机端象限最大高度降到 40vh，避免挤压其他内容 |
| **拖动把手** | 鼠标可以按住任务行的任意非交互区域拖动 | 触摸屏上只有**勾选框**这一处能发起拖动（勾选与拖动把手合并，点勾选框拖动=移动、轻点不移动=勾选）；任务行其他区域不再拦截触摸，正常滚动 |
| **导出**（JSON / Markdown / ZIP） | `<a download>` 触发浏览器下载 | 走原生插件 `ExportFile` 写进系统「下载」文件夹（WebView 不认 blob 下载），成功后提示「已保存到「下载」文件夹」 |

除以上几点外，Bonus、时间视图拖拽记忆、象限底色、完成沉底、日报统计在网页版与 APK 上行为完全一致。

### 面板最大高度
象限（`.quadrant__body`）、时间视图的每个时段块（`.timeview__list`）、计划池列表、模板池列表都设最大高度，超出后各自在右侧出滚动条，不再无限制撑高页面。同一套 CSS 规则同时服务网页版与 APK，仅象限高度在手机端媒体查询里改小。

### 四象限高度（v2.2）
象限容器 `.quadrants` 的网格行高设为 `auto auto` 并 `align-items: start`，四象限各按内容撑开、互不牵制。同一套 CSS 同时服务网页版与 APK，两端无差异。

- **双击任务块 / 双击阶段**：块名 / 阶段名整条标橙；**不会**把块内任务、任务内其它阶段一起标上
- **单击照旧**：点一下文字进编辑、点勾选框勾完成、点按钮触发按钮 —— 高亮只在第二下（`e.detail >= 2`）动手，单击路径一个字节不改
- **双击时正在编辑**：手上没提交的编辑先落下（等于自动提交），再切高亮，不丢字；落点本身在输入框里的点击**不算**高亮候选（在编辑器里双击选词照常）
- **亮度和字高**：底色确为**浅橙**（r > g > b 且足够亮）；底色**盖满字高**（画在 1.6em 行高的内容行上，不是窄条）；浅橙底上的文字对比度 ≥ 4.5:1
- **完成后自动失效**：这一条勾完成后不再显色（恢复普通已完成样式）；取消勾选后高亮**自己回来**；`highlight` 字段全程没被删
- **不参与统计**：加高亮前后完成率、`已完成 / 总数`、Bonus 分母分子、象限计数、日报统计**逐项不变**；排序与自动沉底也不受影响
- **三处都能点**：象限、时间视图、计划池里双击同一个任务 / 块 → 同一条数据的高亮在三个视图里一起变
- **随手带得走**：任务推迟 / 块整体推迟 / 阶段推迟 / 拖回象限 / 池内「导入」/ 按计划日期自动导入 / 模板套用 / 搜索筛选之后，高亮仍在
- **保护模式**：双击点不动，数据一个字节不动（高亮是写操作）
- **拖拽残留点击**：刚拖完那一下触发的点击若已超过双击窗口（1500ms），**不做任何高亮** —— 宁可不动，不标错行
- **JSON 往返**：导出再导入，高亮原样；**导入老版本文件**（没有 `highlight`）正常成功、本地数据一条不动；文件的脏值（`"yes"` / `1` / `null`）当作没高亮
- **以前的版本读新文件**：v2.9 导出的文件仍能被老版本导入（多的字段被忽略），不报错

### v2.10 收尾需求

**需求 1：勾选后不弹回顶部**

- 模板池、阅读栏（含「已读完成」）同样保留位置

- 拖的是同一条数据：文字、完成状态、阶段、槽位、Bonus、高亮全部原样带着走
- 保护模式下拖不动，数据一个字节不动
- 象限里能做到的四类拖动（进块 / 出块 / 顶层换位 / 跨象限），池里都有对应形式

- 文字短、放得下的行**仍然是一行**，不会平白多出空白
- 覆盖任务行、阶段行、任务块头（象限 / 池）、时间视图条目、计划池条目
- 宽屏（> 600px）排版**完全不变**

## 边界情况

### P0：核心功能
- **空阶段名 / 空文本**：trim 后为空则拒绝创建并提示
- **只拆一个阶段**：至少两个阶段名才算「划分阶段」，只有一个时按普通任务处理
- **重复勾选与嵌套完成**：阶段勾完 → 子任务完成 → 块完成 → 大任务完成，逐级回传且不重复计数；回退同理
- **阶段被删光**：父任务回到「没有阶段」的普通形态，父级完成度按子任务重新算
- **跨时段拖拽**：把条目的时段改掉后，时间视图里它要出现在新时段，旧时段不留残影
- **时段为空**：某天只有部分时段有任务时，只渲染有任务的那几列，不出现空板块
- **缓存导入空快照**：没有快照的条目要提示用户先更新快照，不能导入出空数据
- **恢复时父级已删除**：拒绝恢复并说明原因，缓存条目保留在原处
- **大任务名额已满**：新建被拒绝并提示先完成一个
- **推迟到同一天**：同一条任务重复推迟不产生重复副本
- **自动导入与手动删除冲突**：用户删掉自动导入的内容后，同一天不再重复导入
- **跨年 / 跨月**：日期一律 `YYYY-MM-DD`，不出现 `2026-13-01` 这类错误
- **单日 ≥200 条**：渲染与保存仍可用，不卡死、不丢数据
- **全 Bonus 组**：某组一个普通任务都没有时视为未完成，不显示成 0%。「全完成」按「全部 Bonus 都做完」算（v2.5）
- **完成沉底与时间视图记忆**：任务完成后沉底时，时间视图对应时段的顺序记忆同步把该任务键移到末尾，不留下指向已不存在的旧位置

### P1：次要功能
- **非法导入**：JSON 解析失败、非对象、缺必要结构 → 拒绝导入，本地数据一条不变，给出错误提示
- **覆盖导入**：必须二次确认，并提示「建议先导出备份」；取消后不出任何写入
- **导入后视图不同步**：导入完成必须刷新全部视图，不能出现「数据进了但页面还是旧的」
- **手机端为 Capacitor App**：Service Worker 缓存不适用于打包版，代码更新需重新打包；文档里要写清楚，不能让用户以为刷新就能更新
- **离线状态下自动导入**：不需要网络的缓存导入、自动导入必须照常工作

### v2.2 收尾需求
- **导入选择框取消**：取消后不写入任何数据，本地一个字节不动
- **覆盖导入**：覆盖是在一份全新数据上做合并，结果对象不是原来的 `state.data`，实现里要接回引用并重新渲染，不能出现「数据进了但页面还是旧的」
- **池内空块推迟**：块里没有任务时整体推迟也是合法的，只是没有可设 DDL 的任务
- **折叠状态损坏 / 存不上**：读回空表、不崩，也不影响主数据（存不上的界面状态最多回到默认折叠）
- **象限加到开头与时间视图「新增排最前」**（v2.5 统一为同一条约定）：unshift 只作用于象限列表；时间视图里不在 `tv` 记忆中的条目（新增 / 刚设时段）同样排最前，记忆里已有的条目之间仍按 `tv` 排。删除 / 改时段留下的旧键在读取时忽略，不影响排序
- **池内块里的任务被拖回象限**：从宿主块里摘出来（宿主块完成度重算），块被摘空也合法——空块留在池里，可再往里加任务（v2.5 修复：以前这一步会静默失败，拖了没反应）
- **推迟按钮 vs 拖拽**（v2.5 修复）：鼠标按住「推迟」（任务的 / 块头的 / 阶段的）不放、挪动超过拖拽阈值再松开，**不该**变成拖拽或重排，推迟照常触发
- **顺手展开也要落本机**（v2.5 修复）：给折叠着的任务点「＋加阶段」或点阶段改文字时，任务会自动展开——这次展开同样记进本机折叠状态，刷新后仍是展开的
- **块内无阶段任务被推迟光**：块里所有无阶段任务都被单独推迟后，宿主块变成空块，完成度按「空块未完成」重算；块本体仍留在象限里（空块合法，可再往里拖任务）
- **块内无阶段任务推迟到掏空某天**：推迟的收尾与删除一致——某天被掏空时整份日期记录收掉，不留四条空数组
- **搜索时无任何命中**：所有象限 / 时段块显示空白，不报错、不崩；数据一条不动
- **搜索时正在编辑**：点开搜索先把手上没提交的编辑落下，不丢字
- **搜索关键词为空白**：输入框只有空白字符时按「没在搜」处理，显示完整内容

### v2.6 计划池四条
- **拖到自己身上 / 拖出池外**：落点夹紧到合法位置；拖到页面上没有池列表也没有象限的地方，保持上一次落点，松手后不改数据
- **拖到别的池列表**：不支持跨容器，两侧都不变（不自动吸附成「拖进块」）
- **导入的条目已经不在池里**：`NOT_FOUND`，静默跳过、不报错（自动导入重复跑不会出错）
- **当前查看的日期还没有任何数据**：导入时正常建出那一天，条目出现在它 Q-II 的开头
- **计划日期是脏数据**（非法串 / 非日期）：按「未设定」处理，不参与自动导入，也不崩
- **空块 / 块内任务都没设计划日期**：不自动导入（块本体没有计划日期，取不到判断依据）
- **保护模式**：自动导入一次都不执行（保护模式下任何写操作都不放行），池和数据原样不动
- **导出只有一天数据的 Markdown**：正常导出那一天；那一天没有任务时四个象限显示「暂无任务」，不报错

### v2.7 池内任务块对齐象限
- **空块勾选**：块里没有任务时，勾块头没有可设的东西 —— 不报错、块头勾选框也不会停在已勾状态（空块永远算未完成）
- **块本体不沉底**：沉的是**块内任务**，块这个壳留在池里原来的位置（和象限「块本体不沉底」同一条规矩）
- **取消勾选**：勾完再取消，条目留在它沉到的位置，不自动移回原处
- **池内带阶段的任务**：从象限推迟进来的任务可能带着阶段，而池内不画阶段列表 —— 勾它的勾选框按「全部阶段一起勾」处理（和象限同一条口径，避免数据分岔），但用户在池里看不到阶段粒度。属于已知限制（见 DS R-32）
- **保护模式**：池内勾选框和点文字改名都点不动（同其他写操作），池和数据一个字节不动
- **同时在编辑**：勾选 / 改名之前先落手上没提交的编辑，不丢字
- **改块名时块被折叠 / 整个块被删**：编辑态跟着消失，不留孤儿输入框

### v2.8 阅读栏与板块收起
- **文本改/加成空**：拒绝并保留原名（和任务同一条规矩），提示「内容不能为空」
- **起始日期格式不对**（`2026-13-01`、`2026-02-30`、`2026-1-1`、`十月一号`）：拒绝并提示「日期格式不对」；已存在的日期不动。边界上合法的照收（月末、闰年 `2028-02-29`；`2026-02-29` 不是闰年要拒）
- **老的 `HH:MM` 写法**：写操作不收（新数据一律是日期）；只有**读**老文件 / 老数据时才收下并原样保留
- **起始日期清空**：存成「未设定」（显示灰色斜体「未设定」），不是空字符串——避免「没设」出现两种表示。清完编辑框当场收掉（不会停在原地不动）
- **完成后又改起始日期**：允许（需求明说了下方可改），且**不动**完成日期
- **已完成条目没设过起始日期**：那行照样有「未设定」按钮（点得动、能补设），完成日期跟在后面；两个日期相同时仍只画一个
- **勾完成时条目已被删**：`NOT_FOUND`，静默跳过、不报错
- **正在阅读一条都没有、已读完成也一条都没有**：给一句引导文案，不画空列表
- **正在阅读空了但已完成有内容**：正在阅读那句给占位，已完成那段照常画
- **数据里 reading 字段损坏 / 缺失**：缺失补空表；条目没名字 / 日期不合法则丢掉并计数，不影响其它数据、不崩
- **文件的 reading 不合法**：整份拒绝导入并说明原因，本地数据一个字节不动
- **导入时同名文本**：只按**文本**判重，跳过的那条保留本地的日期（起始 / 完成），不被文件覆盖
- **导入的旧版文件（没有 reading 字段）**：正常导入，本地阅读栏一条不动
- **导入 v2.8 初版的文件（阅读栏存的是 `HH:MM`）**：正常导入，老值原样保留
- **收起状态损坏 / 存不上**：读回空表（全部展开）、不崩，也不影响主数据
- **保护模式**：阅读栏的勾选 / 改名 / 设起始日期 / 取消完成 / 删除全部点不动，数据一个字节不动；**收起三角照常能点**（它是纯界面动作，不写数据）
- **阅读栏里正在编辑时点收起**：先把手上没提交的编辑落下，不丢字
- **阅读栏新增时回车 / 失焦 / Esc**：回车提交；失焦也提交（和别处同款）；Esc 取消。内容只有空白时安静取消，不弹「内容不能为空」（用户本来就没想提交）
- **池内块换了外框之后**：块头控件（勾选框 / 块名 / 完成度 / 三角 / 导入 / ＋ / ×）和块内任务的排版、拖拽、勾选行为一个字没动 —— 只换了 CSS 外框

### v2.9 连续双击整条高亮
- **点在控件上**：双击勾选框 / 输入框 / 文本域 / 下拉框 / 按钮 → **不**触发高亮（勾选框该勾的勾、按钮该干的干），避免和原生控件抢第二次点击
- **点在行内空白**：落在那一行的非文字区域，按距离最近的这一条解析（从里往外：阶段 → 任务 → 块），不会标到相邻的块头
- **两下落在不同行**：翻的是**第一下记下的那一条** —— 第二下不重新解析自己的落点。这是**有意**的：第一下已经把这一条开成编辑框，原来的节点被换掉了，第二下再拿 `e.target` 去查会什么都查不到。实际用起来两下离得远时浏览器本来就不算连击（`detail` 回到 1，直接走单击），所以这条只在「真的连击」时才生效
- **双击的两次点击间隔很短**：只切一次高亮（不是「亮→灭→亮」）—— 记下的落点在第二下被消费掉，一条点击链只开关一次
- **同一个任务的两种身份**（块内任务也匹配得到块）：解析顺序是「从里往外」——阶段优先于所属任务、任务优先于宿主块，双击块内任务标的是**任务自己**，不是块
- **落在已删除的那一条**：第二下时先按下第一下的落点**重新查一遍数据**，那一条已经不在了就安静返回（`NOT_FOUND`），不报错、不写脏数据
- **高亮一条不存在的 / 脏 id**：`NOT_FOUND`，静默返回；不会凭空造出一条
- **老数据里的 `highlight`**：缺失没有影响（就是没高亮）；`false` / `0` / 空串 / `null` / `{}` 一律按没高亮算，不写回、不报错
- **暗色主题 / 象限底色**：高亮的浅橙底和深棕字**不跟着变**（主题不覆盖这两个变量），四种象限底色上都能看清
- **高亮的条目被删 / 被清空某天**：和别的字段一样跟着走，不留下解不开的引用；回收站恢复回来后高亮照旧
- **高亮 + 片段高亮并存**：同一条上两种高亮可以同时存在，互不覆盖（片段高亮标的是划选的字，整条高亮标的是这一条的文字行）
- **导出只有一天数据的文件再导入**：高亮原样；那一天没有任务时不报错

### v2.10 收尾需求
- **滚动容器里没有滚动条**（内容没溢出）：记下的位置是 0，贴回去仍是 0，看不出任何差别
- **那一段这次没画出来**（例如搜索把某象限清空了、正好切到了时间视图）：快照按容器身份匹配，找不到就跳过，不报错也不乱贴到别的容器上
- **同一屏里好几个容器同时在滚动**：各记各的（象限按 `data-quadrant`、时间栏按 `data-slot`、池 / 模板 / 阅读各一份固定位置），不会串台
- **拖拽中途松手落在两个区域的缝里**（象限和池之间的空白、面板头部）：落点解析不出来 → **保持上一次的落点**，松手后按那个落点处理；从头到尾都在缝里则什么都不发生
- **拖拽中途把指针移到别的面板上**（模板池 / 阅读栏）：不是合法落点，同上，保持上一次落点
- **池内块折叠着的时候拖东西过去**：块内列表不在 DOM 里，这一处不算落点；想放进块里得先把块展开
- **把一个块拖到它自己身上**：拒绝（数据不动），占位符不出现
- **拖空某一天的最后一个象限条目**：那一天被收掉（不留空壳日期，和「推迟」同一条）
- **拖拽的是一个正在编辑的条目**：先把手上的编辑落下（等于自动提交），再执行这次拖动
- **保护模式**：四种拖动全部无效，数据一个字节不动
- **触摸端轻点勾选框没挪动**：只是勾选，不产生拖动；按住勾选框但移动没过起拖阈值也一样
- **触摸端从勾选框起拖时页面不会跟着滚**（该位置的手势已交给拖拽），从行内别处起手则正常滚动
- **手机上折行之后按钮排在第二行最左**（与勾选框左对齐），点按区域大小不变（仍 ≥ 48px 的可点高度）
  - **v2.11 修订**：折下来那一行改成**靠右对齐、左侧留空**；文字也不再整段掉到第二行（见下）
- **极窄屏（320px）下的长文本**：折行 + `overflow-wrap: anywhere`，不出现横向滚动条、不撑破卡片
- **宽屏**：以上排版规则完全不生效（都在 `max-width: 600px` 里）

### v2.11 收尾需求
- **文字特别长（几百字）**：文字从第一行勾选框右边开始，占满该行剩余宽度后自己往下换行，整条不截断、不出现横向滚动；**第一行不会只剩一个勾选框**
- **文字长度正好卡在临界点**（加上按键差一点点放不下）：按键整组折到第二行、靠右对齐；**不会**出现「前两个按键还在第一行、后两个掉下去」
- **文字短**：照旧一行，按键显示在该行右侧，不折行、不出现多余空白
- **一条任务的按键特别多**（有阶段的顶层任务：完成度 + 三角 + ＋ + 推迟 + ×）：折下来后整组一起靠右；若整组连一行都放不下，按键**组内**再折行，仍靠右对齐，不溢出面板、不撑破卡片
- **正在编辑的任务 / 阶段 / 块**（整条换成输入框）：不涉及按键，行为不变
- **模板池条目、阅读栏条目**：不在本条覆盖范围内（它们不是「任务」），排版沿用各自原有规则
- **极窄屏（320px）**：上述规则照常成立，最长的一行仍是「勾选框 + 文字」
- **宽屏（> 600px）**：那层包裹不生成盒子（`display: contents`），间距与对齐和 v2.10 完全一致

## 遗留问题与后续版本

**以下内容本版不做**，列出来是为了不丢，也为了防止下一版重新讨论一遍。

### 1. 安卓 App 与网页版的数据互通
本版跨设备仍走手动导出 / 导入 JSON。App 与网页版之间自动同步需要云端，而云同步已明确排除（见「非目标」）。**已解决的：手机端粘贴导入 + 电脑端可复制文本导出，这条手动通道要保证好用。**

### 2. 安卓 App 端待修问题
- App 与网页版数据应当能同步（受第 1 条限制，目前只能手动）
- App 的大任务面板在添加新大任务后排版出问题

### 3. 代码结构优化
继续模块化拆分，提升可维护性与运行性能。第一版已经分出「入口 / 交互 / 业务 / 渲染 / 数据」五层，后续新增的模块必须沿用这个分层，不允许把逻辑直接写进入口文件。

### 4. 尚未在真实设备上验收的部分
- 多端并发改动后的合并结果
- 断网 → 改动 → 联网的完整链路
- 现代浏览器之外的兼容性，以及单日 200 条以上的性能基准
- **手机端的排版观感（v2.10 需求 4 + v2.11 需求 1、2）**：窄屏上「文字按回第一行」和「按键整组折到下一行、靠右对齐」都是**浏览器算宽度**的结果，node 里没有排版引擎，只能锁住「让行为成立的那些声明」（`test-mobile-layout.js`）。`max-width: calc(100% - 32px)` 里 32px 的两头余量、以及「装得下 / 装不下」的临界点，要在真机（或 DevTools 手机模拟）实际看一眼；数字真不合适时改的只是那一个数（守卫允许 24~50）
- **APK 已打包但未装到真机**：v2.11 的产物在 `android/app/build/outputs/apk/debug/app-debug.apk`（versionCode 5 / versionName "1.4"），包内容已核对，安装与运行手感未验

这些要在实测之后补测试、补验收记录，**不能提前写成「已完成」**。
